## 1.测试初始化
  - 使用 TestMain(m *testing.M) 和 framen.TestMainRun 替代 initTest
    - 同包下每个Test执行前都会自动调用该函数
  - framen.TestMainRun
    - 单元测试初始化启动框架
    - 包含内容:
      - 启动同包下单元测试(相互不影响)
      - 完成依赖模块(framen.IComponent) 的初始化和生命周期管理
      - 调整logz日志输出格式, 使其更适合单元测试
      - 统一注销 注销 bytedance/mockey 注入

    使用示例:
    ```text
    // 测试启动, 做统一的初始化化工作, 同包下每个Test都会自动调用该函数
    func TestMain(m *testing.M) {
        // 其他初始化逻辑
        // ......
      
        // 测试依赖模块初始化, 及启动测试
        framen.TestMainRun(m,
            conf.New(),
            redisc.New()
        )
    }
    ```

## 2.执行脚本
### 2.1 pre-commit
    - 执行脚本启动命令
    - 每次提交前必须运行(后续将集成到CI/CD中)
    - 将驱动有修改的包(已git add)运行单元测试，并检测测试覆盖率
### 2.2 run-go-unit-test-coverage.sh
    - 单元测试逻辑执行脚本
    - 执行单元测试, 并检测测试覆盖率, 如果覆盖率不达标也会进行报错
    - 有需要时可执行 run-go-unit-test-coverage.sh all , 将执行所有包的单元测试并检测全文覆盖率
## 3. 注入框架
  - testify/mock
    - Go 语言测试框架 Testify 提供的一个常用的 mock 工具包，用来方便地在单元测试中 模拟接口依赖
    - 作用: 提供对 接口化入口的 Mock支持
    - 官网地址: https://github.com/stretchr/testify
    - 使用示例:
      - 简单示例: example/testify
      - 结合service/logic 分层测试: example/mix
  - bytedance/mockey
    - 字节跳动开源 Golang mock 库
    - 作用: 解决单元测试对 非接口化入口 和 外部环境的依赖问题
    - 官网地址: https://github.com/bytedance/mockey
    - 使用示例:
      - 对类的注入: example/testmockey/mock/class_test.go
      - 对函数的注入: example/testmockey/mock/func_test.go
      - 对redis的注入: example/testmockey/mockredis/redis_test.go
    - 推荐用法: 上层接口用 testify.Mock，下层外部依赖用 bytedance/mockey
## 4. Convey 测试框架
  - 适用于复杂测试用例的测试框架
  - 仅作为推荐, 不强制, 按需使用
  - 官网地址: https://github.com/smartystreets/goconvey
  - 推荐文章: https://juejin.cn/post/7130533292310265886
    - 特别是其中 执行顺序 一节
  - 使用示例: example/mockredis/redis_test.go 中 TestRedisByConvey
