## 1. 测试基本要求
1. 所有业务逻辑代码必须具备单元测试，测试覆盖率不得低于 80%（如有覆盖率单独调整需求,可提出,之后修改检查脚本进行支持）。
2. 单元测试必须独立运行，不得依赖外部环境
   - 可通过 mock 方式实现对外部依赖的解耦
   - 强制要求项: 数据库,网络,grpc远程调用 等外部服务
   - 理想情况是mock掉所有对外部包的调用依赖, 让单元测试仅聚焦于当前包下的逻辑 (这里不做强制要求, 仅作为方向建议)
3. 测试代码应与被测代码放在同一模块内，并以 `_test.go` 结尾，例如：`user_service_test.go`。
4. 确保所有单元测试可并行运行，避免共享全局变量或修改全局状态。
5. 每次代码提交前必须运行pre-commit, 执行单元测试
   - 将驱动有修改的包运行单元测试，并检测测试覆盖率。 
   - 需要时可通过 ./run-go-unit-test-coverage.sh all 命令执行所有包的单元测试并检测全文覆盖率

## 2. 代码覆盖率
### 2.1 覆盖率检查
- 覆盖率检查已集成到 run-go-unit-test-coverage.sh 脚本中
- 运行 pre-commit 时会自动调用
- 当出现覆盖率不满足需求的情况是, 会保留对应包的 coverage.out 文件, 可用于查看覆盖率详情

### 2.2 生成覆盖率报告查看
- 对 coverage.out 使用相关命令可查看覆盖率报告详情
- 相关命令:
    - 查看每个函数的覆盖率信息
        - go tool cover -func=coverage.out
    - 生成一个可视化的 HTML 报告
        - go tool cover -html=coverage.out

## 3. 测试方法与原则
### 3.1 使用 `testing` 包编写测试
### 3.2 初始化控制
- 使用 TestMain 作为测试初始化控制
- 调用 framen.TestMainRun 执行依赖模块的初始化工作
    - 参考 [测试初始化](单元测试工具.md#1测试初始化)
### 3.3 表格驱动测试（Table-Driven Tests）
- 使用 表格驱动测试 提高代码可读性和可维护性(基础要求)
- 或 Convey框架替代表格测试 (选用)
- 示例:
```text
func TestMultiply(t *testing.T) {
    cases := []struct {
        name     string
        a, b     int
        expected int
    }{
        {"positive numbers", 2, 3, 6},
        {"zero", 0, 5, 0},
        {"negative numbers", -2, 3, -6},
    }

    for _, c := range cases {
        t.Run(c.name, func(t *testing.T) {
            result := Multiply(c.a, c.b)
            if result != c.expected {
                t.Errorf("Expected %d but got %d", c.expected, result)
            }
        })
    }
}
```

### 3.4 使用 `t.Helper()` 辅助函数
如果有多个测试需要相同的检查逻辑，建议使用 `t.Helper()` 编写辅助函数：
```text
func assertEqual(t *testing.T, expected, actual int) {
    t.Helper() // 标记为辅助函数
    if expected != actual {
        t.Errorf("Expected %d but got %d", expected, actual)
    }
}

func TestSubtract(t *testing.T) {
    result := Subtract(5, 3)
    assertEqual(t, 2, result)
}
```

## 4. 目录与命名规范
### 4.1 目录结构
建议按照 Golang 的 标准目录结构 组织测试代码，例如：

```
/project-root
    /internal
        /service
            user_service.go
            user_service_test.go
        /repository
            user_repository.go
            user_repository_test.go
    /pkg
        utils.go
        utils_test.go
```

### 4.2 测试文件命名
- 测试文件必须以 `_test.go` 结尾，例如：
    - `user_service_test.go`
    - `utils_test.go`

### 4.3 测试函数命名
- 测试函数必须以 `Test` 开头，并遵循 `TestXxx` 形式：
  ```text
  func TestFunctionName(t *testing.T) { ... }
  ```
- 命名规则：
    - `TestFunctionName`：测试普通函数
    - `TestStruct_MethodName`：测试结构体方法
    - `TestPackage_FunctionName`：测试包级别方法

示例：
```text
func TestAddUser(t *testing.T) { ... }
func TestUserService_GetUserByID(t *testing.T) { ... }
```
